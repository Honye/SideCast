## 更新日志

### 2026-11-23 · M5 免费版 / 高级版
- **免费版（FR-ROUTE-03, FR-CONN-09）**：
  - 「应用」区换成一个「Mac 声音」选择器，把 Mac 的全部声音统一输出到一处（本机任一设备或已连接的接收端）；选「这台 Mac（不改变）」时 SideCast 完全不介入。
  - 同时只能连一台接收端：在 Mac 上点连接第二台会弹出升级提示；第二台主动连上来时，给它 2 秒报告自己是否已购买，未购买则断开，并在该设备上说明原因。
- **高级版**：分应用输出 / 音量 / 静音、高级模式、多台设备同时连接。界面上未解锁时显示说明和「了解高级版…」按钮（FR-PAY-01）。
- **解锁规则（FR-PAY-04）**：这台 Mac 有许可证，或任一已连接的接收端在 App Store 买过，连接期间即解锁；断开后恢复免费版，已保存的分应用设置保留，重新解锁后自动生效。失去高级版时，多连的设备只保留最早连上的一台。
- **官网版许可证（FR-PAY-03，LemonSqueezy）**：设置 › 通用 › SideCast 高级版：输入许可证激活、在这台 Mac 上停用（释放激活名额）、购买按钮。许可证存钥匙串；每次启动后台重新校验：服务器明确判定无效（如已退款）则撤销，网络不通时保留，可离线使用；会核对许可证属于 SideCast 对应的商店和商品。
- **iPad 内购（FR-PAY-02/05，StoreKit 2）**：一次性非消耗型商品，支持恢复购买、退款后自动失效、在其他设备上购买后自动同步；App Store 不可用时显示提示和「重试」。
- **修复**：断开连接时先把告别消息发完再关闭，接收端能看到真实原因（之前只显示「连接已断开」）；「全部声音」捕获时排除 SideCast 自己的所有进程（含模拟器里的接收端），避免回授。
- **实测**（Mac + iPad 模拟器 + iPhone 模拟器）：免费版把全部声音送到 iPad（每秒 200 包、丢包 0）；iPhone 作为第二台连接时被断开并显示原因，Mac 弹出升级提示；模拟许可证后两台同时在线；取消许可证后自动断开后连上的 iPhone、保留 iPad；未配置商品信息时激活许可证给出明确提示。
- **测试**：27 个单元测试通过，新增 LemonSqueezy 接口（请求格式、商品核对、错误信息、未配置）、许可证生命周期（激活、重启恢复、离线保留、失效撤销）、StoreKit 本地购买（购买解锁、退款重新锁定）。
- **测试中的一个意外**：验证「全部声音」时，你 Mac 上另一个正在播放的应用的声音有约 1 分钟被转到了模拟器、随后一度被静音（目标离线时按设计静音）。我发现后立即恢复为系统默认，并退出了调试版。

- **设置窗口**（三个页面）：

  - 设备：附近的设备（连接、模式）、已配对设备（显示配对日期，可移除）、本机名称。

- **中英文（7.5 节）**：新增 String Catalog，99 条界面文字 + 权限说明均有简体中文；Mac 和 iPad 实测中文显示正常。
- **iPad 界面**：Mac 列表显示「已配对 / 需配对」，显示本机在 Mac 上的名称；已连接页在没有音频时提示去 Mac 上选择本设备。
- 修复：iOS 模拟器里的 SideCast 进程会出现在 Mac 的应用列表中，现已排除。
- 20 个单元测试通过（新增进程分组、按进程覆盖规则）。

### 2026-11-23 · M3 音频网络传输与 iPad 播放
- **传输**：控制通道协商后，音频走单独的 UDP。每个包用会话派生的音频密钥做 ChaCha20-Poly1305 加密，包头参与认证，按序号防重放；丢包用静音补齐。网络上统一为 48 kHz 立体声，Mac 设备采样率不同时自动重采样。
- **两种模式（FR-MODE-01~04）**：低延迟 = Opus 160 kbps、10 ms 一包、接收端缓冲约 25 ms；高音质 = 无损 PCM 24-bit、5 ms 一包、缓冲约 120 ms。按接收端分别设置并记住，切换即时生效。Mac 菜单栏已连接设备行上有模式选择。
- **iPad 播放**：抖动缓冲 + AVAudioEngine 播放；缓冲过多时轻微丢帧追上，欠载时自动重新缓冲。被来电等打断后，系统建议恢复时自动恢复。
- **接收端控制（FR-RECV-02~04）**：已连接页面有 SideCast 自身的音量滑块（会记住）；连接期间音频引擎持续运行，切后台 / 锁屏继续播放；锁屏 / 控制中心显示「SideCast · 已连接到 xxx」，暂停按钮 = 断开连接，音量用系统滑块。
- **实测**（Mac + iPad 模拟器）：低延迟模式每秒 100 包、丢包 0、缓冲稳定在 1100–1350 帧；高音质每秒 200 包、丢包 0、缓冲稳定在约 5900 帧；Mac 重启后规则自动恢复，重新连接即恢复推流；iPad 切到后台后持续收包。18 个单元测试通过（新增 Opus / PCM 编解码、加密音频包防篡改、环形缓冲）。
- **未验证**：实际听感、真机 Wi-Fi 下的延迟和丢包、真机后台与锁屏表现，需要你在真机上试，见「需要你操作的事项」。

### 2026-11-23 · M2 分应用音频捕获与本地路由
- **应用识别（FR-ROUTE-01/09）**：读取 Core Audio 的进程列表，把辅助进程归到所属应用（例如浏览器的各个辅助进程算作同一个浏览器）。只列出正在发声或设置过规则的应用。
- **分应用路由（FR-ROUTE-02/04）**：每个应用可选「系统默认 / 任一本机输出设备 / 已连接的接收端」。实现方式：给应用建 Process Tap（捕获其声音并让原输出静音），再把发往同一目的地的应用放进一个私有聚合设备里混音输出。切换即时生效，无需重启应用。
- **分应用音量与静音（FR-VOL-01~04）**：0–100% + 静音，带平滑过渡避免爆音；对本机设备同样生效。
- **默认与离线（FR-ROUTE-06/07）**：没设过规则的应用完全不经过 SideCast；目标设备离线时该应用静音等待，界面显示「设备离线」，设备回来自动恢复。
- **持久化（FR-ROUTE-08）**：规则按应用保存，重启 SideCast 后自动恢复（已实测）。
- **安全退出（PRD 7.2）**：Tap 使用「读取时才静音」模式，SideCast 退出或崩溃后各应用自动恢复正常发声。
- **设置窗口**：改为自管理窗口，打开时显示 Dock 图标、关闭后隐藏（PRD 6.8）；再次打开 SideCast 时会弹出设置窗口。目前有「Apps」「Devices」两个页面（临时版，M4 完善）。
- **实测**（本机）：播放 440 Hz 测试音，设为 50% 音量后捕获到的电平与理论值一致（0.015）；改到不存在的设备时显示离线并静音；恢复默认后 Tap 被移除；重启后规则恢复。14 个单元测试通过。
- **尚未用耳朵验证**：我无法听到声音，实际听感（音量变化、切到其他输出设备、有无杂音）需要你试一下，见下方「需要你操作的事项」。

### 2026-11-23 · M1 设备连接与配对
- **设备身份**：每台设备有固定的设备 ID 和 Ed25519 身份密钥（存钥匙串）。
- **加密握手**：X25519 密钥交换 + 双方用身份密钥签名；之后控制通道全部用 ChaCha20-Poly1305 加密，带计数器防重放。同时派生出音频加密密钥，供 M3 使用。
- **配对码（FR-CONN-06）**：任一方不信任对方时，Mac 弹出浮动窗口显示 6 位数字码（2 分钟有效），接收端输入；双方用与本次握手绑定的 HMAC 互相证明，成功后保存信任。输错或超时都会断开，需重新发起。
- **发现与连接（FR-CONN-01/02/08）**：Bonjour `_sidecast._tcp`，开启点对点 Wi-Fi；Mac 和接收端都能发起连接。
- **占用（FR-CONN-10）**：接收端已连着一台 Mac 时，拒绝其他 Mac 并提示「正在被 xxx 使用」。
- **断线重连（FR-CONN-11）**：Mac 对用户想连的接收端，断线后 2 秒自动重试，对方重新出现时也会重试。
- **界面（临时版）**：Mac 菜单栏里列出附近接收端（连接/断开/状态）；iPad 上列出附近 Mac、配对码输入框、已连接页面。完整界面在 M4。
- **测试**：12 个单元测试通过。在本机 Mac + iPad 模拟器（iOS 27.0）上实测：发现 → 输入配对码 → 已连接 → 断开 → 重连免配对码，全部正常。
- 各平台最低版本由 27.2 调为 **27.0**（仍在 27.x 内）：本机模拟器只有 27.0，你的设备是 27.0.1，按 27.2 打的包装不上。

## 技术决策记录

| 决策 | 原因 |
|---|---|
| 单一多平台 target，用 `#if os(macOS)` 区分发送端/接收端 | 共用协议与加密代码；PRD 要求 Mac 接收模式与发送端是同一个 App |
| 官网版也保持 App 沙盒 | 同一份代码后续可直接上 Mac App Store；系统级虚拟音频设备（V1）再以独立驱动安装 |
| 控制通道走 TCP，音频（M3）走单独的 UDP | 控制消息要求可靠有序；音频要低延迟，丢包不重传 |
| Mac 上身份密钥存在登录钥匙串（不是数据保护钥匙串） | 后者需要描述文件授权，开发签名下不可用 |
| 断线后由 Mac 负责自动重连，接收端不主动重连 | 避免两端同时重连互相冲突 |
| 每个应用一个 Process Tap；同一目的地的应用共用一个私有聚合设备，在实时线程里混音 | 改音量只改增益不重建；改目的地只重建受影响的聚合设备 |
| 判断辅助进程属于哪个应用时，优先用系统的「负责进程」接口（非公开，运行时查找），找不到再沿父进程查 | 浏览器、WebKit 等的音频进程大多不是应用本身 |
| Opus 用系统自带的 AudioConverter 编解码 | 不引入第三方库；Mac 与 iOS 都支持 |
| 时钟漂移用「缓冲过多时丢少量帧」处理 | 实现简单；若真机上听到周期性细微咔哒声，再改为微调采样率 |
| 锁屏卡片的「暂停」按钮用作断开连接 | 系统锁屏控件不能自定义按钮文字，PRD 要求的「断开」只能借用暂停 |
| 高级模式按「进程类型」（Bundle ID）设置，而不是按单个进程 | 单个进程每次启动都会变，按类型才能被记住；同类进程（如多个网页 helper）一起设置 |
| App 内切换语言通过写入本 App 的语言偏好实现，重启后生效 | macOS 不支持运行中切换界面语言 |
| 「录制系统音频」权限没有系统查询接口，用「持续捕获到静音」来推测 | 可能误报（例如暂停中的播放器仍输出静音），所以只作为提示文字 |
| 免费版的「全部声音」用一个排除 SideCast 自身的全局 Tap 实现 | 与分应用路由共用同一套引擎；选「不改变」时完全不介入 |
| 许可证离线时保留上次的校验结果，不设离线期限 | PRD 未规定离线期限；只有服务器明确判定无效时才撤销 |

## 已知问题 / 风险

| 问题 | 影响 | 计划 |
|---|---|---|
| 配对码校验用的是「HMAC + 6 位码」，没有使用 PAKE（如 SPAKE2）。若攻击者在配对那一刻实施中间人攻击，可离线穷举 6 位码 | 仅影响首次配对那几十秒、且需攻击者在同一网络主动劫持连接 | 后续换成 PAKE 协议；CryptoKit 没有现成的公开 PAKE 接口，需要自行实现或引入库 |
| 同 Apple ID 自动信任（FR-CONN-05）尚未实现，目前同账号设备也要输配对码 | 首次连接多一步 | M6 实现，需开启 iCloud 能力 |
| 「负责进程」接口不是公开 API | Mac App Store 审核可能不通过 | 官网版先用；上架 App Store 版前评估替代方案（只用父进程关系） |
| 发往接收端的应用即使不出声，Mac 也持续发送静音包（高音质约 2.3 Mbps） | 占用少量带宽和电量 | 后续加静音检测，长时间无声时停发 |
| 菜单栏弹出面板无法用自动化工具点开，界面验证主要在设置窗口里做 | 菜单栏面板与设置页共用同一套行组件，但面板本身只编译验证过 | 请你在实际使用时顺带看一下菜单栏面板 |
| 从终端运行的命令行程序（如 afplay）会被归到启动它的应用下（例如终端） | 显示名可能不直观 | 符合系统的归属关系，暂不处理 |
