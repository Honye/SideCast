## 1. 产品概述

### 1.1 一句话定位
SideCast 让附近的 iPad、iPhone、Vision Pro 或另一台 Mac 成为 Mac 的音频输出设备和屏幕，并且可以为 Mac 上的每个应用单独指定输出设备、单独调节音量。

### 1.2 要解决的问题
- macOS 只能为所有应用选择**同一个**输出设备，无法让「会议走耳机、音乐走音箱」。
- macOS 没有按应用调节音量的能力。
- 手边闲置的 iPad / iPhone 等设备无法作为 Mac 的扬声器使用。
- 想把 Mac 画面放到 iPad 等设备上时，系统自带「随航」只支持 iPad 且不涉及分应用音频。

### 1.3 典型使用场景
1. **iPad 当音箱**：Mac 播放音乐，声音从放在旁边的 iPad 出来。
2. **分应用分设备**：视频会议声音走 AirPods，音乐走 iPad，系统提示音留在 Mac 扬声器。
3. **分应用音量**：把聊天应用的提示音调到 30%，音乐保持 100%，浏览器静音。
4. **副屏**：把 iPad 作为 Mac 的扩展屏，或把 Mac 画面镜像到 iPad，并用手指在 iPad 上点击操作。
5. **多接收端**：同时连接 iPad 和 iPhone，分别承担不同应用的声音或画面。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 发送端 | 运行 SideCast 的 Mac，提供音频与画面 |
| 接收端 | 运行 SideCast 的 iPad / iPhone / Vision Pro / Mac（接收模式） |
| 输出设备 | 任意可发声的设备：Mac 本机扬声器、AirPods、外接声卡/音箱、任一已连接的接收端 |
| 路由规则 | 「某个 Mac 应用 → 某个输出设备 + 音量」的设置 |
| 镜像 | 接收端显示与 Mac 某块屏幕相同的画面 |
| 扩展屏 | 接收端作为 Mac 新增的一块显示器 |
| 官网版 | 通过官网分发、Developer ID 签名并公证的 Mac 版本 |
| App Store 版 | 通过 Mac App Store 分发、运行在沙盒中的 Mac 版本 |
| 高级版 | 接收端在 App Store 一次性购买后的状态，每台设备各自购买，见第 4 节 |

## 3. 平台与分发

### 3.1 平台角色

| 平台 | 角色 | 最低系统 |
|---|---|---|
| macOS | 发送端；同一 App 也可切换为接收模式 | macOS 27 |
| iPadOS | 接收端 | iPadOS 27 |
| iOS | 接收端 | iOS 27 |
| visionOS | 接收端 | visionOS 27 |

### 3.2 分发渠道
Mac 端同时提供 **官网版** 与 **App Store 版**。接收端（iPadOS / iOS / visionOS）通过 App Store 分发。

由于 App Store 版运行在沙盒中，部分能力只能在官网版提供：

| 能力 | 官网版 | App Store 版 | 原因 |
|---|---|---|---|
| 分应用路由与音量（在 SideCast 内设置） | ✅ | ✅（需验证沙盒可用性） | 见 8.1 |
| 接收端出现在系统「声音」设置/菜单中（系统级虚拟音频设备） | ✅ | ❌ | 需安装音频驱动插件，App Store 不允许 |
| 屏幕镜像 | ✅ | ✅ | 公开 API 可实现 |
| 扩展屏 | ✅ | ❌ | 依赖非公开接口 |
| 接收端触控反向控制 Mac | ✅ | ❌（v0.7） | 沙盒内技术上可行，但有 App Store 应用因注入鼠标事件被以 2.4.5 拒绝，见 8.5 |
| USB 有线连接 | ✅ | ❓ 待验证 | 见 8.6 |

**两版差异的处理**（v0.6）：App Store 版中不可用的功能**仍然显示**，但标为「此版本不提供」，**不提官网版**（审核风险见 8.9）。

**上架方式**（v0.6）：Mac App Store 版与 iPad / iPhone / Vision Pro 版放在**同一个 App Store 条目**（Bundle ID `com.imarkr.SideCast`，通用购买）；官网版也使用同一个 Bundle ID，两个版本不能同时安装在一台 Mac 上，换版本时设置保留。App Store 版不使用任何非公开接口（例如判断辅助进程归属的接口，只在官网版使用）。官网版暂不提供自动更新。

## 4. 商业模式

> v0.4（2026-11-23）：LemonSqueezy 不再接受新用户注册，改为「Mac 端免费、接收端在 App Store 收费」。
> v0.5（2026-11-24）：Mac 作为接收端免费；未购买的接收端也可接收屏幕镜像，同时镜像到多台时每台都需要高级版（FR-SCREEN-05/08）。

- **Mac 端完全免费**（官网版与将来的 Mac App Store 版都免费，没有任何收费入口），包括在 Mac 本机上的分应用路由、分应用音量 / 静音和高级模式。
- **接收端（iPadOS / iOS / visionOS）免费下载 + App 内一次性购买「SideCast 高级版」**（非消耗型），**每台设备各自购买**，支持恢复购买。
- **未购买高级版的接收端**：
  - 只能接收 Mac 的「其他声音」，即没有单独设置过的应用的声音；单独设置过的应用照旧按自己的设置输出。
  - 同一时间最多只能连接**一台**未购买的接收端。
- **已购买高级版的接收端**：
  - Mac 可以把单个应用（或高级模式下的单个进程类型）投到这台设备。
  - 不占用上面「一台」的名额，可与其他设备同时连接，数量不限。
- **Mac 作为接收端（接收模式）免费**（v0.5）：视同已购买高级版，可接收单个应用，不占用「一台未购买设备」的名额。官网版 Mac 无法使用 App Store 内购，因此 Mac 接收端不设收费。
- 购买状态只保存在购买的那台设备上（App Store 账户），连接时由接收端告知 Mac；不做服务器端同步。
- 付费机制随 MVP 首发。
- 具体价格上架前再定（见第 11 节）。

## 5. 已确认的需求决策汇总

| 维度 | 结论 |
|---|---|
| 媒体范围 | 音频 + 屏幕（镜像与扩展屏） |

| 分应用路由目标 | 任意输出设备 |
| 多接收端 | 可同时连接多台；每个应用同一时刻只输出到一个设备 |

| 多进程应用 | 默认合并为一个应用；高级模式可展开单独设置每个进程 |
| 未设规则的应用 | 跟随系统默认输出 |
| 目标设备离线 | 该应用静音等待重连，菜单栏标记「设备离线」，设备回来后自动恢复 |
| 设置保存 | 按应用持久记忆，应用重启、设备重连后自动恢复 |
| 音频模式 | 「低延迟」/「高音质」，按接收端分别设置 |
| 画面形态 | 镜像 + 扩展屏（扩展屏仅官网版），所有接收端都支持，可同时投放到多台 |
| 音画关系 | 画面投放与音频路由相互独立 |
| 反向输入 | 接收端触控当鼠标；双指点按 = 右键 |
| 连接方式 | 同一 Wi-Fi 局域网、点对点无线、USB 有线；自动按 USB > 局域网 > 点对点 选择 |
| 配对 | 同 Apple ID 自动信任；其他设备使用 6 位数字配对码（2 分钟有效） |
| Mac 端界面 | 菜单栏 + 设置窗口；Dock 图标仅在设置窗口打开时显示 |
| 接收端控制 | 调整本机总音量；可从接收端发起连接 |
| 接收端后台 | 切到后台 / 锁屏后音频继续播放；锁屏卡片显示信息 + 音量 + 断开 |
| 界面语言 | 简体中文 + 英文；默认跟随系统，可在 App 内切换 |
| 商业模式 | Mac 端免费；接收端免费下载 + 内购一次性买断高级版，每台各自购买；随 MVP 首发（见第 4 节） |
| Mac 端收费 | 无（2026-11-23：先由 Paddle 改为 LemonSqueezy，因 LemonSqueezy 不再接受新用户注册，改为 Mac 端免费） |

## 6. 功能需求

需求编号格式 `FR-<模块>-<序号>`。标 💎 的需求需要**相关接收端**已购买高级版。

### 6.1 设备发现、连接与配对（CONN）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-CONN-01 | Mac 与接收端在**同一 Wi-Fi 局域网**下可互相自动发现 | 两端打开 App 后，对方在设备列表中出现 |
| FR-CONN-02 | 没有路由器时，可通过**点对点无线**直连发现与连接 | 两端均未接入 Wi-Fi 网络（Wi-Fi 开关打开）时仍能发现并连接 |
| FR-CONN-03 | 支持通过 **USB 数据线**连接（适用于 iPad / iPhone，以及支持的 Mac 之间；Vision Pro 不适用） | 插线后设备出现在列表中并标识为「有线」 |
| FR-CONN-04 | 同一接收端有多种通路可用时，**自动**按 USB > 局域网 > 点对点 的优先级选择，通路变化时无缝切换 | 播放中插上 USB 线，连接切到 USB 且声音不中断 |
| FR-CONN-05 | 同一 Apple ID 下的设备**自动信任**，无需配对码。在 Mac 设置中可把某台设备从 iCloud 设备列表移除（所有设备上都不再显示），移除后**不要求配对码**；它再次打开 SideCast 时自动回到列表（2026-11-25） | 同账号设备首次连接不弹出配对码；移除仍在使用的设备后，连接也不弹出配对码 |
| FR-CONN-06 | 非同一 Apple ID 的设备首次连接需**配对码**：Mac 显示 6 位数字，接收端输入，2 分钟内有效 | 输入正确则连接成功；输错或超时则失败，可重新生成 |
| FR-CONN-07 | 已配对设备被记住，下次无需再次配对；可在 Mac 设置中移除信任 | 移除后再次连接需重新配对 |
| FR-CONN-08 | 连接既可从 Mac 发起，也可**从接收端发起** | 在接收端选择一台 Mac 即可完成连接 |
| FR-CONN-09 💎 | 一台 Mac 可**同时连接多台**接收端；其中未购买高级版的最多一台，已购买的不限 | 1 台未购买 iPad + 2 台已购买 iPhone 可同时在线；第二台未购买设备连上时被断开，Mac 提示、该设备说明原因 |
| FR-CONN-10 | 一台接收端同一时刻只能被**一台 Mac** 连接；已被占用时，其他 Mac 无法连接并提示「正在被 xxx 使用」 | 第二台 Mac 尝试连接时失败并看到占用提示 |
| FR-CONN-11 | 连接中断后自动尝试重连，并在 UI 上显示连接状态 | 关闭再打开接收端 Wi-Fi，恢复后自动重连 |

### 6.2 分应用音频路由（ROUTE）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-ROUTE-01 | Mac 端列出当前正在发声或可发声的应用 | 播放音乐的应用出现在列表中，并显示图标与名称 |
| FR-ROUTE-02 | 每个应用可单独选择输出设备，候选项为**任意输出设备**（把单个应用投到某台接收端需要该接收端已购买高级版 💎）：Mac 本机扬声器、蓝牙耳机、外接声卡/音箱、任一已连接接收端 | 将 A 应用设为 iPad、B 应用设为 AirPods 后，两者声音分别只从对应设备发出 |
| FR-ROUTE-03 | 「其他声音」：没有单独设置的应用的声音统一输出到一个设备（Mac 本机设备或任一已连接接收端，含未购买的） | 选择 iPad 后，未单独设置的应用从 iPad 发声，单独设置过的应用不受影响 |
| FR-ROUTE-04 | 每个应用同一时刻**只输出到一个设备**；被路由到其他设备的应用不再从原设备发声 | 应用切到 iPad 后，Mac 扬声器听不到该应用声音 |
| FR-ROUTE-05 | 路由切换即时生效，不要求重启目标应用 | 播放中切换设备，声音在 500 ms 内转移到新设备 |
| FR-ROUTE-06 | 从未设置过规则的应用**跟随 macOS 系统默认输出设备** | 新安装的应用发声时从系统默认设备输出 |
| FR-ROUTE-07 | 目标输出设备离线（接收端断开、AirPods 收盒等）时，该应用**静音等待**；菜单栏中该应用显示「设备离线」标记，不弹系统通知；设备重新上线后自动恢复输出 | 断开 iPad 后该应用无声且有离线标记；重连后声音恢复 |
| FR-ROUTE-08 | 路由设置按应用**持久记忆**：目标应用重启、SideCast 重启、接收端重连后自动恢复 | 退出并重开音乐应用后仍从 iPad 出声 |
| FR-ROUTE-09 | 一个应用的多个进程（如浏览器的辅助进程）默认**合并为一个应用**统一设置 | 浏览器任意标签页的声音都遵循同一条规则 |
| FR-ROUTE-10 | **高级模式**下可展开多进程应用，对单个进程单独设置路由与音量 | 展开后为某一进程单独设置，只影响该进程 |

### 6.3 分应用音量（VOL）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-VOL-01 | 每个应用可单独调节音量，范围 **0–100%**（相对于应用原始音量，不提供增益） | 设为 50% 时音量明显减小；无法调到 100% 以上 |
| FR-VOL-02 | 每个应用提供独立的**静音**开关 | 静音后该应用无声，其他应用不受影响 |
| FR-VOL-03 | 分应用音量与静音状态**持久记忆** | 重启后保持原设置 |
| FR-VOL-04 | 分应用音量对应用路由到的任意输出设备均生效（包括 Mac 本机设备） | 路由到 Mac 扬声器的应用同样可单独调音量 |

### 6.4 音频模式（MODE）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-MODE-01 | 提供「**低延迟**」和「**高音质**」两种传输模式，**按接收端分别设置** | iPad 设为高音质、iPhone 设为低延迟，两者同时生效 |
| FR-MODE-02 | 低延迟模式：优先保证音画同步、适合视频/游戏/会议，使用有损压缩 | 指标见 7.1 |
| FR-MODE-03 | 高音质模式：无损传输，可接受较高延迟 | 指标见 7.1 |
| FR-MODE-04 | 模式设置随接收端持久记忆 | 重连后保持原模式 |

### 6.5 屏幕投放（SCREEN）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-SCREEN-01 | **镜像**：将 Mac 的某块显示器画面镜像到某台接收端 | 接收端实时显示所选显示器内容 |
| FR-SCREEN-02 | **扩展屏**（仅官网版）：接收端作为 Mac 新增的一块显示器，可拖动窗口过去 | 在 Mac「显示器」设置中出现新显示器，窗口可拖入 |
| FR-SCREEN-03 | iPad、iPhone、Vision Pro、Mac **全部支持**镜像与扩展屏 | 四类接收端均可完成镜像与扩展屏 |
| FR-SCREEN-04 | 画面分辨率与比例适配接收端屏幕，不拉伸变形 | iPad、iPhone 上画面比例正确 |
| FR-SCREEN-05 💎 | 可**同时向多台接收端**投放画面（如 iPad 做扩展屏、iPhone 镜像主屏）；同时投放到多台时，**每一台**都需已购买高级版 | 两台已购买的接收端同时显示各自内容；其中一台未购买时，Mac 提示需要高级版 |
| FR-SCREEN-06 | 画面投放与音频路由**相互独立**：开启/关闭画面投放不改变任何应用的音频路由 | 把屏幕镜像到 iPad 后，各应用声音仍按原规则输出 |
| FR-SCREEN-07 | 接收端切到后台时画面停止（系统限制），回到前台后自动恢复 | 切回 App 后画面恢复，无需重新连接 |
| FR-SCREEN-08 | 只投放到一台时，未购买高级版的接收端也可以接收镜像 | 未购买的 iPad 可显示 Mac 镜像 |
| FR-SCREEN-09 | 镜像只能从 Mac 开始；接收端可以**停止镜像**（全屏画面上轻点后出现按钮；Mac 接收端关闭窗口即停止） | 在 iPad 上点「停止镜像」后画面关闭，Mac 上该设备显示为未镜像 |
| FR-SCREEN-10 | 镜像画面中**显示 Mac 的鼠标指针** | 移动鼠标时接收端能看到指针 |

### 6.6 反向触控（TOUCH）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-TOUCH-01 | 在镜像/扩展屏画面上，接收端触控映射为 Mac 鼠标操作 | 单指点击 = 鼠标左键单击 |
| FR-TOUCH-02 | 支持拖动 | 单指拖动 = 按住左键拖动 |
| FR-TOUCH-03 | 支持滚动 | 双指滑动 = 滚轮滚动 |
| FR-TOUCH-04 | 支持右键 | 双指点按 = 鼠标右键单击 |
| FR-TOUCH-05 | 可在接收端开启/关闭触控控制 | 关闭后触控不影响 Mac |
| FR-TOUCH-06 | Mac 作为接收端时，镜像 / 扩展屏窗口里的**鼠标**同样控制发送端 Mac：点击、拖动、右键、滚动、指针移动；同样可开关（v0.7） | 在接收端 Mac 的窗口里点按钮，发送端 Mac 上对应位置被点击 |

不包含：Apple Pencil 压感、接收端键盘输入（见第 10 节）。

### 6.7 接收端 App（RECV）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-RECV-01 | 显示可发现的 Mac 列表与连接状态，可从此发起连接 | 见 FR-CONN-08 |
| FR-RECV-02 | 可调整**本机总音量**（SideCast 播放的整体音量） | 拖动后所有路由到本机的应用声音一同变化 |
| FR-RECV-03 | 切到后台或锁屏后**音频继续播放** | 锁屏后声音不中断 |
| FR-RECV-04 | 后台播放时在锁屏 / 控制中心显示播放卡片：显示所连接的 Mac，提供**音量**调节与**断开连接**按钮 | 在锁屏卡片上点「断开」后连接断开 |
| FR-RECV-05 | 接收端**不提供**修改路由规则和分应用音量的功能（这些只在 Mac 端操作） | — |
| FR-RECV-06 | 支持 iPad、iPhone、Vision Pro 作为接收端 | 三类设备均可连接并播放音频 |
| FR-RECV-07 | Mac 作为接收端时，使用**同一个 SideCast Mac App**，切换为「接收模式」 | 在一台 Mac 上开启接收模式后，另一台 Mac 可发现并连接它 |

## 7. 非功能需求

### 7.1 性能指标

| 指标 | 低延迟模式 | 高音质模式 |
|---|---|---|
| 音频端到端延迟（局域网） | ≤ 50 ms | ≤ 200 ms |
| 音频质量 | 有损压缩，48 kHz | 无损，48 kHz / 24 bit |

| 指标 | 目标 |
|---|---|
| 镜像/扩展屏画面延迟（局域网） | ≤ 100 ms |
| 画面帧率 | 60 fps（网络不佳时自动降级） |
| 路由切换生效时间 | ≤ 500 ms |
| 断线自动重连 | 网络恢复后 5 秒内 |

### 7.2 稳定性
- 长时间（≥ 8 小时）连续播放不中断、不出现明显爆音。
- 网络抖动时优先保证音频连续，可降低画面质量。
- SideCast 异常退出后，各应用声音应恢复从系统默认设备正常输出，不能导致应用「无声」。

### 7.3 资源占用
- Mac 端仅音频转发时 CPU 占用尽量低，不明显影响续航。
- 接收端后台播放时功耗与普通音乐 App 相当。

### 7.4 安全与隐私
- 设备间传输的音频、画面、触控数据全部加密。
- 仅已信任设备可以连接。
- 音频与画面只在本地设备之间传输，不上传到任何服务器。同一 Apple ID 自动信任只在用户自己的 iCloud 中保存设备名称和公钥。
- 不采集音频或屏幕内容用于任何其他用途。

### 7.5 本地化
- 界面支持简体中文、英文；默认跟随系统语言，可在 App 内切换。

## 8. 技术可行性与约束（供开发参考）

> 本节仅记录调研方向与已知限制，不是技术方案定稿。

1. **分应用音频捕获**：可使用 Core Audio Process Tap（macOS 14.4 起提供）捕获指定进程的音频并让原输出静音，再由 SideCast 重新播放到目标设备，从而实现分应用路由与音量。需验证其在 App Store 沙盒下的可用性和审核风险。
2. **系统级虚拟音频设备**：要让接收端出现在系统「声音」设置中，需要安装 AudioServerPlugIn 音频驱动，只能在官网版实现。
3. **屏幕镜像**：可使用 ScreenCaptureKit，两个版本都可用。
4. **扩展屏**：macOS 没有创建虚拟显示器的公开 API，需要使用非公开接口，存在系统升级后失效的风险，仅官网版提供。已实测（2026-11-24，macOS 27.2）：该接口在 App 沙盒内可以创建虚拟显示器，官网版无需关闭沙盒。
5. **反向触控**：向系统注入鼠标事件需要用户在「隐私与安全性 › 辅助功能」中允许；沙盒应用技术上可以使用，但审核有风险（有应用因此被以 2.4.5 拒绝），因此只在官网版提供（v0.7）。
6. **USB 连接**：iPad/iPhone 经 USB 与 Mac 通信需验证可行方案及其在沙盒内的可用性；Vision Pro 没有 USB 数据连接，不适用。
7. **点对点无线**：可使用 Network.framework 的点对点能力，无需路由器。
8. **后台播放**：接收端需开启后台音频能力；画面在后台无法显示是 iOS/iPadOS/visionOS 系统限制。
9. **审核风险**：App Store 审核指南限制在 App 内引导用户到外部渠道购买或获取功能。App Store 版「提示使用官网版」的文案和方式需要谨慎设计，必要时只显示「此版本不支持」而不提官网。收费只在接收端 App 内通过 App Store 内购完成，Mac 端免费，不涉及外部付款。

## 9. 版本分期

| 阶段 | 范围 |
|---|---|
| **MVP** | Mac 官网版 + iPad 接收端；分应用路由（任意输出设备）与分应用音量；Wi-Fi 局域网 + 点对点无线；同 Apple ID 自动信任 + 配对码；持久记忆；菜单栏 + 设置窗口；接收端后台播放；低延迟/高音质切换；中英文；免费 Mac 端 + iPad 内购高级版 |
| **V1** | iPhone、Vision Pro、Mac 作为接收端；USB 有线；屏幕镜像；系统级虚拟音频设备（官网版）；Mac App Store 版上架 |
| **V2** | 扩展屏（官网版）；接收端触控反向控制 |
| **后续候选** | 接收端麦克风作为 Mac 的输入设备 |

分期理由：分应用音频是核心卖点、技术风险集中在 Mac 端，先在一种接收端上打通完整链路；屏幕与反向控制工作量大、依赖非公开接口或受沙盒限制，放在后期。

## 10. 范围之外（已确认不做）

- 跨网络远程投放（不在同一网络/不在附近）
- 同一个应用同时输出到多台设备（多设备同步播放）
- 多台 Mac 同时连接同一台接收端
- Apple Pencil 压感输入、接收端键盘输入回传 Mac
- 在接收端修改路由规则或分应用音量
- 场景预设（如「办公」「观影」一键切换）
- 分应用音量超过 100% 的增益
- 购买状态的服务器端同步（账号体系、跨设备离线解锁）
